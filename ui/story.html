What am I looking at?
  • MafLM is a tiny ternary language model trained on children's stories. It reads and writes one byte (one character) at a time, so each byte is one position, up to a 256-byte window.
  • Type a prompt and press Generate. Every position runs on the target and on the golden model (an independent Python copy of the same integer arithmetic). It counts as checked only if both pick the same next byte and their 64-bit logits checksum (a fingerprint of all 256 scores) is equal.
  • Greedy always takes the top-scoring byte, as the timed runs do. A temperature samples from the scores instead (higher = more random); the seed makes it repeatable.
  • KV cache: what the model remembers of earlier positions. Attention reads all of it, so each byte costs a little more than the last.
  • The tree twin replaces each feedforward layer with a small binary tree: 3 left/right decisions (L/R) pick one leaf of 80 neurons, so it reads 1/8 of the weights. The dense twin reads them all.
  • Times are the board's cycle counts (none for the golden model). Per-stage shares need a profiling build (-DLM_PROFILE=ON).

Fair reading: the controlled comparison is the tree twin against the dense twin (same runtime, data and board). Atome is an outside reference only. Its own engine recomputes the whole context for every byte, includes its prompt in each timed call and only fits a 24-byte window on the board; the MafLM numbers exclude the prompt. So the gap compares engines, not models. Details in notes/lm.md, "Fairness of the Atome comparison".
